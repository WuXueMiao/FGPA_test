## 1. 项目目标与版本规划

**实现一套真正运行在易灵思 FPGA 上的实时视觉系统：摄像头采集彩色图像，FPGA 完成灰度化、可选中值滤波与 Sobel 边缘检测，再把原始灰度和边缘结果同时送到显示器。**

项目重点不是单独写出一个 Sobel 公式，而是贯通“采集—缓存—计算—对齐—显示”，并能解释数据怎样流动、跨域怎样处理、资源与延迟怎样测量。


基础作品能够连续显示真实相机图像及其边缘；面对棋盘格、文字、几何图形或人物轮廓时结果可解释；运动时不出现长期错位、错行或撕裂；同时交付 RTL、约束和演示视频。

完成版在基础上增加**中值滤波、实时阈值调节、彩色边缘叠加和运行状态统计**。前三项在题目高阶挑战中明确列出；统计用于证明稳定性，是本方案建议补充的能力。


| 版本 | 功能范围 | 完成判据 |
|---|---|---|
| V0：平台贯通 | 下载、彩条、摄像头直通 | 采集—显示链路可运行，尺寸和时钟可测 |
| V1：基础交付 | 灰度、窗口、Sobel、参数化阈值、同时对比显示 | 基础条目逐项有证据，算法逐像素比对通过 |
| V2：推荐参赛 | V1 + 中值 + 动态阈值 + 彩色叠加 + 统计 | 可稳定切换，坐标对齐，连续运行测试通过 |
| V3：进阶展示 | DDR 冻结/回放、Canny 或形状识别等 | 每项独立验证，不破坏 V1/V2 稳定性 |

## 3. 七个容易误读、但会影响方案的事项

### 3.1 中值滤波的要求层级

指南第 12 页的背景和任务描述提到中值滤波，第 14 页正式将其列为高阶挑战。[G2][G3]

这属于原文层级上的差异，不应默默改写成“绝对必做”或“绝对可省略”。

**建议**：先完成不含中值的基础链路，正式作品尽量加入中值与开关。若只准备最小版本，向组委会确认验收口径。

### 3.2 “零延迟”不是物理上的 0 ms

原文以“零延迟”形容流水线实时效果，同时要求两行缓存。[G2][G4]

**【推导】**中心像素的下方、右方邻居尚未输入时，不可能完成完整 3×3 计算，必然存在邻域等待、寄存器、跨域及显示扫描延迟。

应分别报告吞吐率、像素处理延迟和整机曝光到显示延迟。采用“行级流式”“算法无需等待整帧”等准确描述，不应宣称严格 0 ms。

### 3.3 显示 60 Hz 不等于采集 60 张不同图像/秒

原文明确显示端最低模式，采集端明确最低分辨率，但没有另列基础采集最低 FPS。[G2]

若相机 30 fps、显示约 60 Hz，需要重复展示完整源帧或其他经过验证的转换机制，不能将重复刷新算作新采集帧或新处理结果。

### 3.4 同标称频率不代表同步

指南给出同频简化设计、异频采用异步 FIFO 的提示。[G4]

但两个独立 25 MHz 时钟仍可能相位不确定、长期漂移；行帧总长与消隐也可能不同。FIFO 能解决跨域与有限突发，不能永久抵消平均速率差。

只用行缓存的方案必须有实际节奏和占用量证明。

### 3.5 DDR“硬核”需要核对实际器件和板级设计

原题提到调用 Efinity 的 DDR 硬核控制器。[G3]

**【外部核查】**官方型号资源表区分硬核能力，Ti60 不能直接套用较大型号的硬核 LPDDR4/4x 控制器配置；这也不意味着 Ti60 不能通过适配的方案连接板级 DDR。[E1][E3]

应取得本板已验证的 DDR 例程，核对控制器名称、软/硬实现、颗粒、接口、许可证与时钟。

本文称“板级 DDR 控制器封装”，不预设一个尚未确认可用的硬核。

### 3.6 芯片相同不代表开发板相同

赛题四是 VF-Ti60F225。指南第 21 页的某个通用 Ti60F225 产品页面则列有 HyperRAM 等另一套开发套件配置，不应当作 VF 的原理图或引脚表。[G1][G5][E4]

相似教程使用的相机、HDMI 发送器和存储颗粒也不能直接视为本板配置。

### 3.7 VGA、220 MHz 和“5 周期”要区分表述层级

背景/任务提到 HDMI/VGA，但基础显示条目明确写 HDMI。[G2]

默认准备 HDMI；只交 VGA 前先确认。

指南中的 Sobel 220 MHz、典型中值网络 5 周期是技术提示，不是你们的实测成果，也不是基础条目列出的必达指标。[G4]

最终频率由真实器件上的时序报告证明，延迟由实际寄存器结构定义。

## 5. 总体架构与技术路线

### 5.1 共同的算法链

```text
相机 → 配置/接收/像素解包 → RGB → 灰度 → 可选中值 → Sobel → 阈值
                               │        │                       │
                               └─原始RGB/灰度保留与对齐──────────┤
                                                                ▼
                                                    同帧、同坐标合成
                                                                │
                                                    分屏/画中画/彩色叠加
                                                                │
                                                    显示缓冲与扫描 → HDMI
```

跨域、行调度、可选 DDR 属于搬运层，图像算术属于算法层，不应全部混入一个顶层状态机。

### 5.2 路线 A：行级流式

```text
camera_pclk 域             proc_clk 域                       display_clk 域
接收/组装 → 异步 FIFO → 灰度/中值/Sobel/对齐 → 行级缓冲与跨域 → 扫描输出
```

适用于采显长期速率、行帧节奏和相位控制已证明可匹配，或本板已有验证过的无整帧缓存链路。

算法缓存少、等待短，但显示端必须按固定扫描时刻获得正确像素，启动预填充和行调度是实质任务。

不能默认相机 FPS 正好等于刷新率、独立时钟不会漂移或 FIFO 可以永远兜底。无法证明时，应选择路线 B。

### 5.3 路线 B：DDR 完整帧解耦

```text
采集：相机 → 接收/组装 → 写 FIFO → DDR 完整源帧
                                      │
                               帧描述符/所有权管理
                                      │
显示：HDMI ← 扫描/行缓冲 ← 合成 ← 行流水线算法 ← DDR 读出
```

适用于采显帧率不同、需要冻结/回放/完整双视图，或稳定板级例程本身依赖 DDR。

算法仍按行/像素流水线运行，读取和预取由调度器控制；没有新源帧时重复最后完整帧，但重复刷新不算新增源帧。

代价是帧管理、访存和帧级延迟。

“使用 DDR”不等于算法不是流水线，“算法是流水线”也不等于整机无帧延迟。

### 5.4 路线决策

| 真实情况 | 建议 |
|---|---|
| 已有稳定相机—HDMI 例程 | 沿用其时钟/搬运架构，优先插入算法 |
| 无 DDR，但能可靠匹配采显 | 路线 A，先验证水位不会长期漂移 |
| 30 fps 相机对约 60 Hz 显示，不能锁定 | 路线 B，完整帧重复显示 |
| 需要冻结/回放/任意双视图布局 | 路线 B 更易调度 |
| 计划完整 Canny 滞后连接 | 提前规划帧级状态与访存 |

控制面只负责相机配置、阈值、模式与状态，初期状态机/寄存器即可。

算法模块不直接读物理按键、不初始化相机，也不直接驱动 HDMI 引脚。

## 6. 统一数据接口与时序规则

### 6.1 先统一协议，再分工

可采用轻量像素流，不必为形式强行引入 AXI。

调试版建议显式携带坐标和帧身份，优化时可重建部分字段。

| 字段 | 含义与规则 |
|---|---|
| `pixel` | 模块固定格式与位宽，如 RGB888、Gray8、11 位幅值 |
| `valid` | 当前拍有有效像素，只有接受有效像素才推进窗口 |
| `sof/eol/eof` | 当前流首像素、每行末像素、图像末像素，与数据绑定 |
| `x/y` | 原始图像坐标，明确原点和裁边规则 |
| `frame_id` | 源帧身份，用于对齐和重复帧识别 |
| `cfg_epoch` | 本帧配置版本，防止半帧改阈值 |

真实相机通常不能随内部 `ready=0` 停下来，因此必须区分可反压的内部流与不可反压的物理输入。

接收缓存不足属于设计问题，不能静默丢像素。

### 6.2 三种有效信号

`display_de` 表示扫描位于可见区；`pixel_valid` 表示此拍存在传输；`window_valid` 表示 3×3 邻域完整。

它们不能短接，帧头、行头尤其如此。

### 6.3 推荐边界策略：内区计算，最终画布补边

| 链路 | 输入 | 内区输出 | 原图坐标原点 |
|---|---|---|---|
| Sobel | W×H | (W−2)×(H−2) | (1,1) |
| 中值→Sobel | W×H | (W−4)×(H−4) | (2,2) |

内部仅输出完整邻域，即 valid-only。

最终格式恢复模块把结果放回 W×H 画布，边界填黑；不能把 HDMI 改成 638×478。

最终填黑也不等于算法输入先补零，这两种方法结果不同。

中值输出有效行宽已变为 W−2，后续 Sobel 窗口不能仍按 W 计数。

裁边后的 `sof/eol/eof` 要按新输出重新产生，而非机械延迟输入标志。

### 6.4 气泡与排空

行列状态只随有效像素更新；固定延迟算术流水线仍需传播在途数据和 valid，不能遇到输入空拍就冻结整个下游，否则行尾/帧尾像素可能无法排出。

模块说明要区分“时钟周期延迟”和“有效像素使能次数”，消隐存在时两者不同。

### 6.5 配置按帧提交

按键修改影子配置，处理新源帧时提交，并与该帧绑定；或者等旧帧完全排空再修改活动配置。

不能让仍在流水线的旧帧读到新阈值。

中值开关改变路径延迟和有效尺寸，初版宜在帧边界切换、重建窗口有效状态、按坐标恢复画布，而不是用组合多路器随时切换。

### 6.6 复位与恢复

各域按实际 IP 要求复位，在时钟稳定后同步释放；考虑 PLL、DDR 校准、相机配置、接收和显示的先后。

帧开始清理计数和窗口有效标记，通常不必逐位清整片 BRAM。未初始化的 Ti60 RAM 内容不能假定为零。[E1]

残缺行、溢出或相机重启应产生错误状态，并在合法帧边界重新同步；丢弃异常半帧是恢复策略，不可据此声称全程无丢帧。

## 7. 基础算法的硬件实现

### 7.1 先正确解包颜色

相机可能输出 RGB565、RGB888、YUV 或 Bayer RAW，具体以真实配置为准。优先使用已验证 RGB 模式。

RAW 需要另做解包/去马赛克，不能用一条灰度公式代替；YUV 直接取 Y 的捷径也应说明处理边界并确认验收口径。

RGB565 可按以下规则扩成 RGB888：

```text
R8 = {R5, R5[4:2]}
G8 = {G6, G6[5:4]}
B8 = {B5, B5[4:2]}
```

8 位 DVP 传 RGB565 时，所选模式通常需两个字节组成一个像素，PCLK 每拍不一定是完整像素。

字节顺序、采样边沿、HREF/VSYNC 极性必须按器件资料，残缺字节不能跨行拼接。

### 7.2 灰度化与定点位宽

**【工程建议】**采用：

```text
Y = (77×R8 + 150×G8 + 29×B8 + 128) >> 8
```

系数和为 256，+128 用于舍入；不是原题固定系数。

原题要求 DSP 或移位加法、避免除法器。[G2]

移位表达式为：

```text
77×R  = (R<<6)+(R<<3)+(R<<2)+R
150×G = (G<<7)+(G<<4)+(G<<2)+(G<<1)
29×B  = (B<<4)+(B<<3)+(B<<2)+B
```

最大累加值含舍入为：

```text
256×255+128 = 65408
```

16 位无符号可容纳。

必须先扩位再移位相加，避免表达式按 8 位截断。可先做两/三级寄存器，后续按时序优化。

测试黑、白、纯 RGB、均匀灰和随机输入。上述公式对应黑/白 0/255，纯红/绿/蓝 77/149/29；参考模型要与 RTL 的舍入完全一致。

### 7.3 滑动窗口的坐标语义

当前接收原图 `I(x,y)` 时，窗口为：

```text
p00=I(x-2,y-2)  p01=I(x-1,y-2)  p02=I(x,y-2)
p10=I(x-2,y-1)  p11=I(x-1,y-1)  p12=I(x,y-1)
p20=I(x-2,y)    p21=I(x-1,y)    p22=I(x,y)
```

结果属于中心 `(x−1,y−1)`，不是当前输入 `(x,y)`。

前两行提供同列像素，三组横向寄存器提供最近三列，只有 x≥2、y≥2 才有完整窗口。[G2][G4]

```text
当前输入 ──────────────────► 当前行横向移位
   └→ 一行有效像素延迟 ────► 上一行横向移位
          └→ 再延迟一行 ───► 上两行横向移位
```

“行延迟”以有效像素为单位，不是随意实例化同深度 FIFO 即可。

同步 BRAM 的读、地址、写回和当前像素旁路延迟必须一起设计。

推荐 `line_delay` 对外承诺：第 n 个有效输入对应第 n−W 个有效像素的输出，内部封装 RAM 时序。

实际 RAM 模式支持读旧值、读新值和可选输出寄存器等不同语义；异步地址冲突尤其不能假定读到旧值。[E2]

### 7.4 小矩阵先验收窗口

测试图 `I(x,y)=10y+x`，尺寸 8×6。

当前输入 (2,2) 时首窗口必须为：

```text
 0  1  2
10 11 12
20 21 22
```

下一像素窗口向右移一列。

检查换行、第二帧换图、插入 valid 空拍和中途复位，确认不跨行拼接、不混旧帧。

每完整帧窗口数应为：

```text
(W−2)×(H−2)
```

### 7.5 Sobel 核与表达式

**【原题明确】**[G2]

```text
Gx 核：          Gy 核：
-1  0 +1        -1 -2 -1
-2  0 +2         0  0  0
-1  0 +1        +1 +2 +1
```

硬件表达式：

```text
right  = p02 + 2*p12 + p22
left   = p00 + 2*p10 + p20
bottom = p20 + 2*p21 + p22
top    = p00 + 2*p01 + p02

Gx = right-left
Gy = bottom-top

G = abs(Gx)+abs(Gy)

edge = (G > threshold)
```

`>` 是本方案选定规则，原题未规定等于阈值的归属；所有模型和 RTL 必须统一。

### 7.6 位宽表

| 数据 | 范围/上界 | 位宽建议 |
|---|---|---|
| 灰度 | 0…255 | 8 位无符号 |
| 四个加权和 | 0…1020 | 10 位无符号 |
| Gx/Gy | −1020…1020 | 11 位有符号 |
| 绝对值 | 0…1020 | 10 位无符号，或统一扩成 11 位 |
| G | 分量独立上界给出的安全上界 2040 | 11 位无符号 |
| 阈值 | 本方案配置域 0…2047 | 11 位无符号 |
| 边缘 | 0/1 | 内部 1 位，显示映射到 0/255 |

2040 是保守安全上界，不表示两个分量最大值能在同一窗口同时出现。

减法前将 10 位无符号和补零并明确转为 11 位有符号；累加前扩位。

不要先截成 8 位再求绝对值，负梯度会丢失，这类问题在 OpenCV 官方梯度教程也有说明。[E6]

阈值作用于完整 G。

幅值可视化另做饱和或缩放，不能直接取低 8 位造成回绕。

### 7.7 四级流水线

| 级 | 运算 | 同步传递 |
|---|---|---|
| S1 | 四个加权和 | 中心坐标、valid、帧身份、配置 |
| S2 | Gx/Gy | 同上 |
| S3 | 绝对值与累加 | 同上 |
| S4 | 阈值比较 | 同上及重新生成的流边界 |

与指南思路一致。[G4]

时序不足可增加级数。

四级并行流水线能让四个像素同时处于不同阶段、填满后每拍一个结果；用一个运算单元串行花四拍后才接下一个像素，吞吐率并不相同。

### 8.2 相机模块的状态与边界

配置状态机包括上电等待、释放复位、检查标识/连接、写模式、完成/失败。

I²C 与相机 SCCB 细节按真实器件处理，不能一概假定应答相同。

`config_done` 不足以证明模式正确，还需实测像素数和帧周期。

DVP 检查采样边沿、同步极性与字节配对，行末残字节不能留到下一行。

MIPI 优先用适配本板和 Ti60 的接收例程/IP，再处理数据类型、虚拟通道和解包；初期不同时自研协议、去马赛克和全部算法。

### 8.3 窗口模块应可复用

参数包括数据宽度、有效行宽、有效高度及坐标原点。

可复用于中值、高斯、Sobel、NMS，但每级数据含义不同。

同一灰度窗口可以并行供多个原图算子使用，然而“中值后的 Sobel”必须建立中值结果的新窗口，不能直接拿最初的灰度窗口替代。

### 8.4 对齐模块不能只写成“延迟四拍”

路径涉及灰度算术、窗口中心偏移、RAM、滤波、第二个窗口、Sobel、跨域和显示调度。

固定时序被证明后可以用延迟链实现；开发阶段用 `(frame_id,x,y)` 检查，不靠目测调拍数。

需要彩色叠加时必须保留原始 RGB。

将灰度复制三份不是“原始彩色”。

中值开/关改变延迟与内区，必须分别验证。

### 8.5 顶层与模块交付

顶层只做实例化、连线、时钟复位、配置和状态汇总，不把所有外设及算法放进一个巨大 `always`。

每个模块需说明格式、时钟域、坐标、复位、延迟单位、是否可反压、测试方法与厂商 IP 依赖。

## 9. 显示、分屏与原图对齐

### 9.1 HDMI 包括扫描与物理链路

扫描计数器输出 RGB/HS/VS/DE 不等于 HDMI 已完成。

板上若有外部发送器，需要配置并满足并行输入时序；若 FPGA 直接输出，需要适配本板的编码、串行化和 I/O。

初版集中视频，题目没有额外要求音频。[G2]

### 9.2 常见 640×480、约 60 Hz 参考时序

外部原始参考是 Linux 内核模式表，不是指南新增指标。[E5]

| 项目 | 水平 | 垂直 |
|---|---:|---:|
| 可见区 | 640 | 480 |
| 前肩 | 16 | 10 |
| 同步脉宽 | 96 | 2 |
| 后肩 | 48 | 33 |
| 总长 | 800 | 525 |
| 极性 | 负 | 负 |

25.175 MHz 像素时钟对应：

```text
25,175,000 / (800×525) ≈ 59.9405 Hz
```

应采用本板和显示器支持的模式；指南中的 25 MHz 是近似提示，不能写成精确标准值。[G4]

### 9.3 分区显示不等于完整双视图

同坐标分区模式在左半显示原始灰度、右半显示对应位置边缘，适合首先调试；但左右实际是场景的不同区域。

完整双视图在左右各放一张完整缩略图，需要缩放、地址映射和读出重排，不能只靠 `x<W/2` 选择信号。

原题没有展开具体缩放布局。[G2]

正式展示建议完整双视图或画中画；仅裁切分区是否足够应确认，不能默认为肯定符合所有验收理解。

DDR 路线可将同帧原图与边缘映射为两个 320×240 缩略图，再布局到 640×480。

行级路线可先对每行水平 2:1 抽样、借助行缓存先输出原图再输出边缘，但会横向压缩；若再要保比例、纵向缩小和任意居中，需要额外行/帧调度，不能默认几个寄存器就能做到。

### 9.4 扫描供给与换帧

显示行提前准备，计入 BRAM 读取与算法等待。

帧地址和布局在显示帧边界切换，不可扫半帧换地址。

欠载时可输出故障底色并计数，但只是可观测机制，正常运行欠载不能当作达标。

## 10. 缓存、带宽与时钟域设计

### 10.1 吞吐率计算

**【推导】**有效像素率：

```text
R = W×H×不同源帧FPS
```

| 示例模式 | 有效像素率 |
|---|---:|
| 640×480×30 | 9.216 Mpixel/s |
| 640×480×60 | 18.432 Mpixel/s |
| 1280×720×30 | 27.648 Mpixel/s |
| 1280×720×60 | 55.296 Mpixel/s |

这些是预算示例。

II=1 的算法核需有足够长期能力，同时满足连续突发或以缓存吸收；平均值足够不代表瞬时不会溢出。

可以按真实链路选择 50/100 MHz 等初期目标，再验证时序，没必要一开始追 220 MHz。

### 10.2 行缓存与 BRAM 粒度

两行 640×8 灰度需要：

```text
2×640×8 = 10240 bit = 1280 byte = 1.25 KiB
```

中值与 Sobel 各自窗口按四行预留约 2.5 KiB 逻辑数据，不包括 RGB 对齐、CDC、显示缓存和 RAM 深宽浪费。

**【厂商资料】**Ti60 有 256 个 10 Kbit RAM 块、160 DSP 和 62,016 逻辑单元，支持的 RAM 深宽模式单列在手册。[E1]

**【推导】**所有 RAM 理想相加约 320 KiB，但任意数据宽度并不能获得全部容量：以 1024×8 模式存 640×480 灰度，需要 300 块，超过 256 块。

紧密打包可能改变分配，但还需给算法和 FIFO 留空间，不能默认整帧灰度可直接放片上。

| 640×480 单帧格式 | 字节 | KiB |
|---|---:|---:|
| 1 位边缘，紧密打包 | 38,400 | 37.5 |
| 8 位灰度 | 307,200 | 300 |
| RGB565 | 614,400 | 600 |
| RGB888 | 921,600 | 900 |

尤其不要把 2.6 Mbit 误读为 2.6 MB。

基本算法用行缓存，真正需要整帧时优先外部存储。

### 10.3 FIFO 不能消除长期速率差

```text
Q(t) = Q(0) + 累计写入Nw(t) − 累计读出Nr(t)

ΔQ(t) ≈ (R_in−R_out)×t
```

平均差值不为零且没有调速/帧转换，有限 FIFO 最终一定满或空。

深度应由最坏突发、停顿和频偏预算得到；可仿真累计差值的最大值减最小值，再加安全裕量并选择预填充。

差值长期漂移，先改架构而非只加深 FIFO。

### 10.4 CDC 按对象处理

| 对象 | 建议机制 | 错误做法 |
|---|---|---|
| 像素与元数据 | 双时钟 FIFO 整包传输 | 每位各接两级触发器 |
| 单比特稳定状态 | 合适同步器 | 直接组合使用异步状态 |
| 短脉冲 | 握手/toggle | 假设目标域一定采到 |
| 多位配置 | 稳定数据+握手或配置 FIFO | 各位独立同步后当一致数值 |
| 帧完成/地址 | 描述符与所有权握手 | 标志和地址分离而不保证对应 |
| 跨域计数 | 一致性快照 | 直接读取变化中的二进制总线 |

约束不能用大范围假路径掩盖未实现的 CDC。

外设输入输出延迟应来自真实硬件，而非任填数字。

### 10.5 DDR 带宽预算示例

假设 RGB565 原帧按 30 fps 写、按约 60 Hz 每刷新完整读一次，算法在读取后流式运行：

```text
写：640×480×2×30 = 18.432 MB/s
读：640×480×2×60 = 36.864 MB/s

有效载荷合计：55.296 MB/s
```

若预算有效利用率 60%，原始带宽需约 92.16 MB/s；60% 是假设，不是板上实测。

结果写回、多视图重复读取、Canny 状态访问要逐项计入。

应测试实际混合读写持续吞吐，不只引用标称峰值。

### 10.6 帧所有权

帧槽可设：

```text
FREE / WRITING / READY / READING
```

只写空闲槽，完整帧完成才发布，显示只读完整帧，正在读取不能覆盖。

异步场景可考虑三缓冲，但任何有限槽数都不能解决输入长期快于消费的问题。

冻结显示不等于停止采集。采集继续而显示不消费时，有些帧必然不显示，需记录策略。

重复显示、不显示、输入异常丢弃应分别统计，不能都归为“无丢帧”。

## 11. 具体实施步骤：从空工程到可交付作品

遵循指南的彩条→相机直通→灰度→Sobel→高阶顺序，并补充独立仿真与验收。[G4]

### M0：核实平台与路线

填写硬件事实和工具版本，运行最小工程，确认相机格式/节奏、HDMI 驱动、采显匹配方式。

产出时钟域图、资料索引和路线 A/B 决策。

资料不全时可以并行模型和窗口仿真，不应猜板级引脚。

### M1：只做显示彩条

不用相机，显示彩条、灰阶、棋盘与边框，验证通道、可见区、时钟和发送器。

产出彩条例程版本、照片与扫描计数波形。

稳定、完整、无漂移后才进入下一步；黑屏先查板级链路，不改 Sobel。

### M2：真实相机直通

完成配置、接收、像素组装、必要跨域或 DDR，先显示彩色原图。

统计行长、帧高、源帧周期与错误。

颜色正确、尺寸符合设置、正常工况无持续水位漂移/溢出/欠载才通过。

### M3：整数参考与测试向量

固定颜色扩展、灰度系数、Sobel、阈值、裁边与元数据约定，准备阶跃、棋盘、细线、随机图。

产出模型与逐阶段期望值。

附录 A 可直接起步，但不能让默认参数不同的库函数代替全部算法规范。

### M4：灰度仿真与上板

独立测试整数结果和 valid 延迟，再接相机显示。

产出 `tb_rgb_to_gray`、比对结果和灰度版本。

插入模块后，尺寸、源帧统计与稳定性应不受破坏。

### M5：攻克窗口

先 8×6，后 640×480；测试空拍、连续帧、复位、错误行，核对实际 RAM。

产出窗口序列与有效数。

首尾、换行、跨帧均正确，每帧 `(W−2)(H−2)` 个窗口，才接入 Sobel。

### M6：Sobel 数值与上板

分阶段验证加权和、符号差、绝对值、完整幅值和阈值，保留调试输出。

正反阶跃均正确、没有下溢或截断，内区与模型逐像素一致，再观察真实视频。

### M7：对齐、同时显示，冻结 V1

保留未滤波原始灰度，按帧和中心坐标对齐；实现分屏/画中画、画布恢复和预取。

建立 B1—B10 证据，打 `v1.0-baseline` 标签。

只全屏切换而从不同时显示二者，不应自动算作完成分屏/画中画要求。

### M8：高收益增强，冻结 V2

建议顺序是：

```text
动态阈值 → 中值 → 彩色叠加
```

一次只插入一个新功能，每次完整回归。

产出开关、交互、同输入对比和 `v2.0-enhanced`。

关掉扩展应回到基线行为，不能引入半帧参数切换或坐标漂移。

### M9：选择一个重点进阶

DDR 若是主链路刚需，应前移 M2；此时只新增冻结/回放。

Canny 与识别先选一个主攻，独立分支验证算法定义、资源和最坏性能。

明确完整还是近似，不把实验分支直接替换稳定演示。

### M10：时序、长测与交付冻结

审查约束和 CDC，检查布局布线，长时间运行、多次上电，从干净目录重建。

产出源码/IP/约束、版本哈希、报告、接线与下载说明、演示视频。

最终阶段不再引入架构级改动。

## 12. 六项高阶挑战的完整实施路线

### 12.1 A1：3×3 中值滤波去噪

**原题**：灰度后、Sobel 前取 9 像素中位数，使用合理并行比较网络，抑制椒盐噪声。[G3]

```text
Gray8 → 窗口1 → median_3x3 → 窗口2 → Sobel
```

两套窗口的数据含义不同，采用 valid-only 时有效尺寸逐级减小。

#### 第一版建议：9 阶段奇偶交换网络

输入编号 0…8：

```text
偶数阶段：(0,1)、(2,3)、(4,5)、(6,7) 比较交换
奇数阶段：(1,2)、(3,4)、(5,6)、(7,8) 比较交换

交替执行9阶段，每阶段寄存；取最终下标4。
```

每个比较单元输出最小/最大值。

完全展开为 36 个比较交换单元，9 个寄存器阶段，填满后每拍接新窗口；串行状态机每 9 拍接一组不等于该吞吐。

本次文档准备中，软件检查了 9 个秩值全部 362,880 种排列与 100,000 组随机 8 位窗口，该网络中位数正确；这不证明 RTL、时序或上板已通过。

指南的典型 5 周期是优化提示，不应为了凑周期使用错误近似。[G4]

#### 不要把不完整排序当作中位数

**不要把“一次行排序+一次列排序的中心”当成必然中位数。**

原文只给策略提示而没展开完整网络。[G4]

反例：

```text
输入（行已排序）：      列排序后：
1 2 9                 1 2 7
3 4 8                 3 4 8
5 6 7                 5 6 9
```

中心仍是 4，真正中位数为 5。

该反例是工程核验，不是在替原文补出未给出的完整算法。

#### 验收与演示

先验证随机、极值、重复值，再验证图像内区和两个窗口串联。

演示必须同图同噪声同阈值比较滤波开/关，同时观察噪点降低与细线损失。

验收包括真中位数、持续吞吐、边界和切换后的坐标。

### 12.2 A2：实时阈值调节

**原题**：按键/拨码调阈值，含消抖与寄存器，+ 提高阈值、− 降低阈值。[G3]

```text
按键 → 同步 → 消抖 → 单次事件 → pending配置 → 帧级握手提交 → active配置
```

可先用默认 160、步长 16、范围 0…2047，均为方便操作的起始选择，不是最佳参数。

加减先扩位再饱和，不回绕；两键同时按定义无动作或恢复默认。

消抖约 10—20 ms 量级只是起点，以真实波形确认，长按连发另作规则。

建议 OSD 显示阈值/模式，初期也可串口；多位配置不能直接跨域。

固定输入下采用 `G>T` 时，增大 T 的边缘数应不增加；运动相机场景不适合直接检验该单调关系，应冻结或用向量。

单击事件、上下限和帧级生效均需验收。

### 12.3 A3：帧缓存与 DDR

**原题**：完整图像写入 DDR，分离采集/存储/读取/处理，可做回放、冻结和多帧对比。[G3]

控制器先按实际板卡核验。

#### 实现顺序

先 DDR 自检：初始化/校准、全零全一、交替位、地址相关数据，覆盖地址范围和突发边界。

再固定图案帧显示，之后接相机，最后交互功能。

#### 模块划分

```text
ddr_ip_wrapper
frame_writer
frame_reader
frame_arbiter
frame_descriptor
```

描述符记录基址、宽高、行跨度、格式、源帧 ID、完整状态与配置版本。

读预取保障扫描，写端也不能无限饥饿，以水位和最坏停顿做预算。

#### 冻结与回放

冻结显示是固定读取完整源帧，不等于停止采集。

建议冻结源帧后仍可调阈值重新计算，便于严格同图对比。

回放用有限帧队列和明确覆盖策略，只声明真正保存的历史帧。

#### 验收

不读半帧、不覆盖正在读的帧、帧边界切换、冻结/解冻稳定、回放序号正确、混合读写吞吐满足预算。

主要风险是板级配置、跨域描述符、撕裂、欠载和帧延迟，不能只做 UI 即视为完成。

### 12.4 A4：Canny 边缘检测

**原题完整链**：

```text
高斯滤波
    → 梯度幅值和方向
    → 非极大值抑制
    → 双阈值分类
    → 滞后边缘连接
```

依据：[G3]。

OpenCV 原始说明也强调弱边缘是否连接到强边缘。[E6]

仅 Sobel+双阈值不能称完整 Canny。

#### 步骤一：参考定义

固定高斯核、边界、L1/L2 范数、方向量化、NMS 等值规则、阈值与 4/8 邻接，各阶段都有期望图。

#### 步骤二：高斯与梯度

初版可用 3×3 权重：

```text
1 2 1
2 4 2
1 2 1
```

归一化除以 16，可用移位近似。

核尺寸是本方案选择、非原题指定。

说明舍入、位宽，再复用 Sobel。

#### 步骤三：方向与 NMS

量化 0/45/90/135 度，用符号和绝对值比值比较替代浮点反正切，记录固定点分界。

NMS 沿梯度方向比较两邻居，因此需缓存梯度幅值/方向的新邻域，不是复用原始灰度窗口。

相等平台规则影响边缘厚度，要用斜线/细线验证，不能仅“加入 NMS”就保证单像素。

#### 步骤四：双阈值

输出非边缘/弱边缘/强边缘三种状态，约定 `T_low<T_high` 和等值归属，可用 2 位编码。

#### 步骤五：滞后连接

可理解为以强边缘为种子，在候选边缘图上做可达性传播，保留所有连接到强边缘的弱像素。

链条可能很长并沿扫描反方向延伸，局部 3×3 检查或固定一两轮传播不能保证完整结果。

完整实现可用帧级状态图与工作队列等经过验证的连通算法，预算最坏队列容量、重复入队、随机访存、终止条件和溢出处理。

队列满静默丢节点不是正确算法。

若只做局部单遍，应明确命名“局部连接近似 Canny”，不可省略说明。

#### 验收

特别加入长弱链末端连强点、孤立弱链、跨行回折链，比较声明的参考算法。

同时报告不同源帧处理 FPS、最坏延迟、存储和资源。

来不及时保留稳定 Sobel，把 Canny 子模块作为实验成果，不冒充完整功能。

### 12.5 A5：彩色边缘叠加

**原题**：边缘彩色线叠加原始彩色图，处理 RGB 三通道。[G3]

最简覆盖规则：

```text
edge=1：输出 (255,0,0)
edge=0：输出对应的原始 RGB
```

红色是演示选择，不必做透明混合。

真正难点是 RGB 与边缘同帧同中心坐标，包含中值开/关、RAM、跨域及画布恢复。

非边缘位置应逐像素保留原始颜色，不能拿灰度复制三通道冒充彩色。

验收用固定高对比矩形、细线和缓慢移动物体，边缘线贴合原图；两个滤波模式都验证。

这项视觉收益高，新增算术少，建议进入 V2。

### 12.6 A6：简易目标识别

**原题**：边缘基础上识别圆/矩形等，通过轮廓和几何特征判断并显示结果。[G3]

#### 先限定场景

初版限定干净背景、高对比、有限目标数与缓慢运动，明确适用范围。

链路可为：

```text
边缘
    → 必要修补/去噪
    → 轮廓/连通区域
    → 面积、周长、包围框等特征
    → 规则分类
    → 框/文字输出
```

修补会改变边缘，需说明并保留旁路。

#### 特征设计

矩形考虑长宽比、线段/角点与包围框关系；圆考虑中心距离分布或圆度。

若用：

```text
圆度 = 4πA/P²
```

A 必须是围成面积、P 有明确周长定义，不能把边缘像素数当填充面积或把包围框面积当真实面积。

旋转、缺边和噪声要测试。

#### 硬件约束

全帧轮廓/标签等价合并复杂，可限制 ROI、目标数量与轮廓长度，但须定义溢出行为。

低频决策可以有明确软硬分工，核心图像链仍在 FPGA。

#### 验收

建立含不同尺寸角度、光照、背景及无目标的固定测试集，报告误报/漏检。

识别结果带帧 ID，处理滞后时不能把旧帧框直接贴到新帧并声称正确实时跟踪。

### 12.7 进阶取舍

| 组合 | 建议 |
|---|---|
| 阈值+中值+彩色叠加 | 优先形成完成度高的推荐版本 |
| 再加 DDR 冻结/回放 | 有稳定 DDR 或主链路需要时很合适 |
| 再加完整 Canny | 有存储/RTL/验证能力时重点攻关 |
| 再加限定形状识别 | 强化应用场景，严格报告边界 |
| 一开始同时做全部 | 无明确人力与时间冗余时不推荐 |

## 13. 自选增强：服务验证和展示

本节不是原题六项挑战，属于团队自选。

### 13.1 状态可观测性

建议采集帧数、不同源帧处理数、刷新次数、FIFO 溢出、显示欠载、错误行/帧和配置状态都有记录。

串口/OSD 读取一致快照，不直接读异步变化的多位计数。

可观测性往往比再堆一个算法更能提升调试效率与报告可信度。

### 13.2 可控噪声与同输入对照

灰度后可加可关闭的椒盐噪声注入，固定种子、规则与实际比例，明确标注人工噪声。

比较中值前后时必须同源图同噪声同阈值，优先冻结帧或离线固定向量，不把相机自然变化误当算法改进。

### 13.3 自适应阈值

可统计上一帧幅值分布来决定下一帧阈值，但要明确目标是分位数、边缘密度或其他规则。

直方图不能自动保证“语义上更好的边缘”。

该功能增加统计存储与跨帧状态，应在手动阈值稳定后做，并保留手动回退。

### 13.4 提高分辨率/FPS

指南提到算法复杂度与帧率是考核维度，但未给本题统一的更高分辨率硬指标。[G2]

可把 720p 等作为自主目标，前提是相机、接口、存储、显示均支持，报告真实处理尺寸与不同源帧能力。

把低分辨率图放大不等于提高算法处理分辨率。

## 14. 测试、正确性与性能评价

### 14.1 建立四层验证体系

**第一层：算法数值正确。**

给定明确输入和参数，灰度、中值、Gx/Gy、G、边缘结果与整数参考模型一致。

**第二层：流时序正确。**

加入空拍、换行、换帧和复位后，像素顺序、窗口中心、有效输出数量与元数据仍正确。

**第三层：板上系统正确。**

相机输入、显示、跨域、DDR 及交互共同运行时，没有隐藏的数据损坏和正常运行欠载。

**第四层：工程可复现。**

源码、IP、约束和环境记录能够重建当前演示版本；测试结论能追溯到版本和配置。

仅凭显示器上“看起来像边缘”只能作为第三层的一个视觉线索，不能替代前两层验证。

### 14.2 必做测试矩阵

下表为本方案建议的测试，不是官方额外提交项目。

| 测试输入/情形 | 检查目标 | 预期或判断规则 |
|---|---|---|
| 全黑、全白、均匀灰 | 常量、溢出、阈值规则 | 内区 G=0，`G>T` 且 T≥0 时无边缘 |
| 黑→白与白→黑竖直阶跃 | 有符号 Gx | 梯度符号相反，边缘位置和幅值对应 |
| 水平阶跃 | Gy 与行方向 | 与参考模型完全一致 |
| 斜线、单像素细线 | 邻域与方向 | 不要求主观“漂亮”，先要求模型一致 |
| 编号小矩阵 | 窗口顺序 | 9 个数据、中心坐标都正确 |
| 棋盘格 | 高频输入、行列错位 | 无意外周期性条带，与模型一致 |
| 随机 RGB/灰度 | 算法一般情况 | 逐像素数值一致 |
| 椒盐噪声、重复值窗口 | 中位数正确性 | 输出是 9 个值中第 5 小的值 |
| G 恰好等于阈值 | 比较边界 | 按本方案 `>` 规则输出非边缘 |
| 阈值上下限、连续按键 | 配置溢出与消抖 | 饱和、不回绕、事件次数符合规则 |
| 输入插入气泡 | 使能与流水线排空 | 没有跳像素、冻结尾部或错位 |
| 两帧使用完全不同图案 | 帧间污染 | 第二帧不混入第一帧窗口内容 |
| 帧中复位/相机重启 | 恢复机制 | 丢弃不完整帧并报告，后续整帧恢复 |
| 长度错误的行/残缺字节 | 接收鲁棒性 | 错误可观测，不跨行错误拼接 |
| 两个独立时钟轻微频偏 | 长期匹配 | 检查水位漂移；不允许只观察几秒 |
| 最大输入突发/DDR 暂停 | 缓存预算 | 支持工况内不溢出、不欠载 |
| 显示模式/中值开关切换 | 配置与路径对齐 | 按帧切换，无新旧帧混合 |
| 红色边缘叠加 | 原始 RGB 对齐 | 非边缘保持原 RGB，边缘贴合坐标 |
| DDR 冻结、解冻、回放 | 帧所有权 | 不读半帧、不覆盖正在读的帧 |
| Canny 长弱边缘链（选做） | 完整滞后连接 | 与声明的参考算法一致，区分近似 |
| 无目标、干扰图形（选做） | 识别误报 | 报告误识别和漏检，不只展示成功样本 |

### 14.3 逐像素比对的报告格式

建议每次失败打印：

```text
frame_id、x、y、stage、expected、actual、config
```

比如只给一个“比较失败”没有定位意义；给出错误发生在第 1 行、第 639 列附近，则往往直接指向行边界或 RAM 延迟。

需要同时比对**数据与有效数量**。

如果丢了 100 个像素后只拿剩下部分比较，也可能错误地得到“100% 一致”。

每帧输入和输出数量、首尾标记都应作为独立断言。

对于本文固定的整数算法，数值正确性目标应为完全一致；若某项有意使用近似，应单独报告误差与原因，不能把设计缺陷笼统称为量化误差。

### 14.4 区分“实现一致性”和“图像效果”

与整数参考模型的逐像素一致，证明实现了指定算法，不等于该算法在所有场景下效果最佳。

效果评价需要另一个参照：如合成图形的真实轮廓、同一干净图的结果、人工标注，或明确的应用判据。

有真实边缘参照时，可以报告精确率、召回率、F1 或 IoU；允许边缘位置容差时，要写清楚匹配半径。

**不能只报告普通像素准确率**，因为边缘图中非边缘通常占多数，输出大量黑色可能得到很高的表面准确率。

中值滤波实验至少比较“Sobel”和“中值+Sobel”在同源帧、同噪声、同阈值下的输出，同时观察噪点抑制与细节损失。

改变阈值、光照或视角后的效果不能当作纯粹的滤波消融。

### 14.5 性能指标的统一口径

| 指标 | 应如何报告 | 常见误报 |
|---|---|---|
| 采集分辨率 | 接收端实际 W×H | 把显示放大后的尺寸当作输入尺寸 |
| 采集 FPS | 单位时间实际完整源帧数 | 把 HDMI 刷新次数当作采集数 |
| 算法吞吐率 | 有效像素/秒，注明持续/突发与 II | 把 Fmax 直接当作实际像素速率 |
| 不同源帧处理 FPS | 去除重复源帧后的完成数/时间 | 相同帧被重复计算也算新增帧 |
| 显示刷新率 | 显示扫描帧数/秒 | 与源帧更新速度混为一谈 |
| 算法延迟 | 指定像素入口到对应结果的时间 | 只统计最后四级寄存器 |
| 整机延迟 | 明确是否含曝光、DDR、显示器 | 用“肉眼实时”代替测量 |
| FPGA 资源 | 完整工程布局/综合报告 | 只报告 Sobel 子模块、忽略接口 |
| 时序结果 | 实际工作时钟、约束完整性和裕量 | 无约束路径未检查却说时序通过 |
| 稳定性 | 运行时长、有效帧数、错误计数 | 短视频无异常就宣称永不丢帧 |
| 功耗（自选） | 仪器/工具、测量边界、运行模式 | 把整板功耗直接当算法核功耗 |

### 14.6 延迟应当怎样计算

**【推导】**对于逐行、无填充的 W×H 输入，若忽略额外寄存器并把有效像素从 1 开始计数，第一个完整 3×3 窗口需要等到第 `2W+3` 个有效像素。

它对应原图中心 `(1,1)`，不是对应帧首像素。

这叫**帧启动到首个内区输出的等待**。

对已经进入稳态的某个中心像素而言，则需要等到其下一行、下一列的邻居到达，再加算术和搬运延迟。

两个测量起点不同，不能混成同一个数字。

中值与 Sobel 串联时，首个最终内区像素属于原图 `(2,2)`，其原始数据依赖范围已经扩展到 5×5。

在同样忽略消隐和寄存器的模型中，至少需要看到原图 `(4,4)`，即第 `4W+5` 个有效像素。

实际时间还取决于行消隐、有效脉冲节奏、RAM 读取、跨域预填充和输出扫描。

**50 MHz 下四级算术寄存器约 80 ns，只是运算段的示例延迟，不是整机延迟。**

建议用源帧 ID 与像素坐标在仿真中打时间戳；上板可用 GPIO 对关键事件打点测量处理段，或使用高速录像测整机光学响应。

两种测量覆盖的系统边界应分别注明。

### 14.7 连续运行与异常测试建议

内部验收可分成三级：单功能调试连续约 5 分钟、整链路集成约 30 分钟、交付前更长时间稳定运行并多次重新上电。

这些时间是建议门槛，不是原题规定，也不构成无限期可靠性的证明。

正常工况和故障注入应分别记录。

正常工况目标是无意外输入丢帧、错行、FIFO 溢出和显示欠载；故障注入目标是错误可检测、不会永久卡死、可在下一个合法边界恢复。

### 14.8 最终性能结果表：开发后填实测值

| 项目 | 测试条件 | 实测值 | 证据路径 |
|---|---|---|---|
| 输入模式 | 相机/格式/分辨率/FPS | 待测 | `reports/capture/` |
| 显示模式 | 时钟/分辨率/刷新率 | 待测 | `reports/display/` |

### 15.4 约束与时序的最低审查项

所有真正使用的时钟有清楚的定义，生成时钟关系正确；相机输入和显示输出按真实外设时序约束；异步跨域有相应结构与约束；复位和例外路径可解释；必要路径没有被遗漏或随意假路径化。

时序不满足时，应先定位长组合路径、高扇出、存储读出和跨域错误，再决定加寄存器、改存储结构或调整时钟。

不能只降低时钟到“编译通过”，却不重新验证摄像头持续输入时的处理能力。

## 16. 团队分工、关键路径与时间安排

### 16.1 三人团队的建议分工

| 角色 | 主责 | 与其他人的接口 |
|---|---|---|
| A：平台与视频链路 | 相机、HDMI、时钟/CDC、需要时的 DDR | 输出规范像素流，接收完整显示行/帧 |
| B：算法与数值验证 | 灰度、窗口、中值、Sobel；后续 Canny | 严格遵守位宽、坐标和流协议 |
| C：系统集成与测试 | 配置/按键、合成对齐、测试脚本、统计、演示与文档 | 维护系统回归、需求追踪和最终工程 |

角色 C 不应被安排成“只写报告”：原图对齐、模式切换、显示布局和稳定性验证本身都是实质技术任务。

资源有限时可以合并角色，但不能省掉集成负责人。

若有第四位成员，可负责 DDR/Canny/识别之一的独立扩展和实验，不建议把所有尚未确定的高阶挑战同时分配给其承担。

### 16.2 可以并行的工作

A 在调试彩条与相机直通时，B 可以完成整数模型和小矩阵窗口仿真，C 可以建立仓库、接口契约、测试向量和状态统计框架。

这样不必所有人等待板卡接通后才开始。

但模块集成前必须冻结接口语义。

只约定“8 位输入、8 位输出”是不够的，还要约定帧边界、有效像素、裁边、延迟和配置生效时机。

### 16.3 真正的关键路径

```text
真实板级资料与可运行例程
    → 稳定相机采显链路
    → 正确窗口与 RAM 时序
    → 数值正确的 Sobel
    → 原图/边缘同帧同坐标对齐
    → 基础验收与时序收敛
    → 推荐扩展与最终交付
```

项目拖延常见于前两步和“对齐/跨域”，不一定出在 Sobel 加减法。

进度跟踪应围绕可验证的里程碑，而不是已写多少行 RTL。

### 16.4 六周参考计划

指南估计，有一定 Verilog 与外设驱动基础的团队，基础要求约需 3—4 周，加入中值与阈值等部分高阶功能约需 5—6 周。[G4]

下表沿用这个量级作工程安排，不是针对尚未了解基础的团队作工期保证。

| 周次 | 主目标 | 本周必须留下的成果 |
|---|---|---|
| 第 1 周 | 平台、彩条、相机接收；模型与接口并行 | 能显示原图，或已定位阻塞原因；模型与接口草案 |
| 第 2 周 | 稳定直通、灰度、窗口仿真 | 窗口序列正确，灰度上板通过 |
| 第 3 周 | Sobel、原图对齐、基础布局 | 完整基础功能，开始连续运行与问题闭环 |
| 第 4 周 | V1 冻结、时序和稳定性；阈值交互 | 基础验收证据、可回退版本 |
| 第 5 周 | 中值、彩色叠加；按需 DDR 功能 | 推荐完成版，严格同输入对比 |
| 第 6 周 | 补充一个成熟扩展或只做收尾 | 干净构建、实测报告、演示视频、最终版本 |

如果 DDR 是采显链路前提，应从第 1 周就开始验证，不要在第 5 周才发现必须引入它。

如果团队 FPGA 基础较弱或没有可运行板级例程，应增加前期学习与外设调试缓冲。

### 16.5 截止日期临近时怎样取舍

只剩约 2—3 周且主链路尚未稳定时，优先完成基础闭环、阈值交互和可信测试，暂缓完整 Canny、复杂识别、网络功能。

对中值滤波的最终提交要求，应结合前述原文层级差异确认。

最后一周不再重构数据协议或更换摄像头；最后阶段保留一份已经验证的配置文件、源代码标签、接线照片和恢复操作。

新增功能不影响稳定版，是最重要的止损机制。

## 附录 A：可用于 RTL 比对的整数参考模型

### A.1 范围与使用方式

下面的代码定义了本文建议的 RGB888 灰度公式、可选 3×3 中值、3×3 Sobel、`G>T` 阈值以及 valid-only 内区/最终黑边策略。

它用于离线验证，**不能替代 FPGA 端实现**。

输入为 `H×W×3`、`uint8`、RGB 顺序的 `.npy` 数组；RGB565 必须先按所选规则扩展为 RGB888。

若图像来自 OpenCV 常见的 BGR 读取路径，应先交换通道。

输出 `.npz` 包括灰度、滤波内区、Gx/Gy、完整位宽幅值、完整边缘画布、有效掩码及原图坐标偏移。

将以下 Python 代码保存为 `golden_model.py`，在安装 NumPy 的环境运行：

```bash
python golden_model.py --self-test

python golden_model.py input_rgb.npy \
    --threshold 160 \
    --out sobel_ref.npz

python golden_model.py input_rgb.npy \
    --threshold 160 \
    --median \
    --out median_sobel_ref.npz
```

本次文档准备时，代码已在本地执行自检；还需由你们的 testbench 将 RTL 输出按同样坐标和格式导出后，完成真实逐像素比对。

它没有验证摄像头配置、CDC、HDMI、DDR 或实际 FPGA 时序。

```python
"""整数参考模型：离线验证用，不代替 FPGA 处理。"""

from __future__ import annotations

import argparse
from pathlib import Path

import numpy as np
from numpy.lib.stride_tricks import sliding_window_view


def edge_reference(
    rgb: np.ndarray,
    threshold: int = 160,
    use_median: bool = False,
) -> dict[str, np.ndarray]:
    """生成灰度、中值、Sobel 与二值化的整数参考结果。"""

    if not isinstance(rgb, np.ndarray):
        raise TypeError("rgb 必须是 NumPy 数组")

    if rgb.ndim != 3 or rgb.shape[2] != 3 or rgb.dtype != np.uint8:
        raise ValueError("输入必须是 H×W×3、uint8、RGB 顺序")

    h, w, _ = rgb.shape

    if min(h, w) < (5 if use_median else 3):
        raise ValueError("图像尺寸小于当前算法的有效邻域")

    if (
        not isinstance(threshold, (int, np.integer))
        or not 0 <= threshold <= 2047
    ):
        raise ValueError("threshold 必须是 0..2047 的整数")

    # 必须先扩位，再乘加或减法。
    c = rgb.astype(np.uint32)

    gray = (
        (
            77 * c[..., 0]
            + 150 * c[..., 1]
            + 29 * c[..., 2]
            + 128
        ) >> 8
    ).astype(np.uint8)

    src, origin = gray, 1

    if use_median:
        nine = sliding_window_view(gray, (3, 3)).reshape(
            h - 2, w - 2, 9
        )
        src = np.partition(nine, 4, axis=-1)[..., 4]
        origin = 2

    q = sliding_window_view(src.astype(np.int32), (3, 3))

    gx = (
        q[..., 0, 2]
        + 2 * q[..., 1, 2]
        + q[..., 2, 2]
        - q[..., 0, 0]
        - 2 * q[..., 1, 0]
        - q[..., 2, 0]
    )

    gy = (
        q[..., 2, 0]
        + 2 * q[..., 2, 1]
        + q[..., 2, 2]
        - q[..., 0, 0]
        - 2 * q[..., 0, 1]
        - q[..., 0, 2]
    )

    magnitude = (np.abs(gx) + np.abs(gy)).astype(np.uint16)

    edge_full = np.zeros((h, w), dtype=np.uint8)
    mask = np.zeros((h, w), dtype=np.uint8)

    ys = slice(origin, h - origin)
    xs = slice(origin, w - origin)

    edge_full[ys, xs] = (
        (magnitude > threshold).astype(np.uint8) * 255
    )
    mask[ys, xs] = 1

    return {
        "gray_u8": gray,
        "filter_valid_u8": src,
        "gx_roi_i16": gx.astype(np.int16),
        "gy_roi_i16": gy.astype(np.int16),
        "magnitude_roi_u16": magnitude,
        "edge_full_u8": edge_full,
        "valid_mask_u8": mask,
        "origin_xy_u16": np.array(
            [origin, origin], dtype=np.uint16
        ),
        "threshold_u16": np.array(
            threshold, dtype=np.uint16
        ),
        "median_enabled_u8": np.array(
            use_median, dtype=np.uint8
        ),
    }


def self_test() -> None:
    """验证常量图、正反阶跃及滤波开关下的基本性质。"""

    for med in (False, True):
        for value in (0, 64, 255):
            image = np.full((12, 16, 3), value, np.uint8)
            out = edge_reference(image, 0, med)

            assert np.all(out["gray_u8"] == value)
            assert not out["edge_full_u8"].any()

        step = np.zeros((12, 16, 3), np.uint8)
        step[:, 8:] = 255

        a = edge_reference(step, 160, med)
        b = edge_reference(255 - step, 160, med)

        assert a["edge_full_u8"].any()

        assert np.array_equal(
            a["edge_full_u8"],
            b["edge_full_u8"],
        )

        assert np.array_equal(
            a["gx_roi_i16"],
            -b["gx_roi_i16"],
        )

    print("模型自检通过；不代表 RTL 或板上验收通过。")


def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)

    parser.add_argument(
        "input",
        nargs="?",
        type=Path,
        help="RGB888 uint8 .npy",
    )
    parser.add_argument(
        "--out",
        type=Path,
        default=Path("reference.npz"),
    )
    parser.add_argument(
        "--threshold",
        type=int,
        default=160,
    )
    parser.add_argument(
        "--median",
        action="store_true",
    )
    parser.add_argument(
        "--self-test",
        action="store_true",
    )

    args = parser.parse_args()

    if args.self_test:
        self_test()
        return

    if args.input is None:
        parser.error("指定输入 .npy，或使用 --self-test")

    try:
        rgb = np.load(args.input, allow_pickle=False)

        result = edge_reference(
            rgb,
            args.threshold,
            args.median,
        )

        args.out.parent.mkdir(
            parents=True,
            exist_ok=True,
        )

        np.savez_compressed(args.out, **result)

    except (OSError, ValueError, TypeError) as exc:
        parser.exit(1, f"运行失败：{exc}\n")

    print(f"已保存：{args.out}")


if __name__ == "__main__":
    main()
```

### A.2 输出如何与 RTL 对照

`gx_roi_i16`、`gy_roi_i16`、`magnitude_roi_u16` 只包含合法内区；`origin_xy_u16` 说明该数组左上角对应的原始图像坐标。

`edge_full_u8` 则已恢复成输入尺寸，外围按本文约定填黑。

不要把 RTL 中 1 位边缘 `0/1` 直接与显示用 `0/255` 比较；先统一编码。

也不要把延迟造成的行列偏移当成数值误差，应先按源帧与坐标匹配，再对比数值和数量。

这个参考模型故意不调用默认边界条件不一致的库 Sobel/Canny 来充当全部规范。

后续添加新模式时，应先在 `algorithm_spec.md` 写清楚定义，再修改参考模型与测试向量。

## 附录 B：常见故障的定位顺序

| 现象 | 优先排查 | 不建议首先做的事 |
|---|---|---|
| 显示器始终黑屏 | 电源、时钟、复位、引脚、HDMI 发送器与标准时序 | 反复调 Sobel 阈值 |
| 彩条正确但相机黑屏 | 相机上电/配置、PCLK、HREF/VSYNC、数据接收 | 重写显示扫描 |
| 图像颜色怪异或周期性条纹 | RGB/BGR、RGB565 字节顺序、有效像素组装 | 先增加滤波 |
| 每行错一两像素 | RAM 读延迟、行计数、窗口列移位、DE 对齐 | 随意把整条链多延迟一拍 |
| 每隔一段时间滚屏或卡顿 | 时钟频偏、缓存水位、帧率差、帧所有权 | 仅把 FIFO 深度翻倍后停止验证 |
| 黑白反向边缘不对称 | 无符号减法、符号扩展、绝对值、8 位截断 | 归因于相机曝光 |
| 顶部或左侧出现异常边缘 | 窗口预填充、边界策略、旧帧残留 | 用裁切隐藏全部问题 |
| 加中值后图像错位 | 第二级行宽、两级坐标偏移、路径延迟 | 只调整 RGB 的固定延迟猜数 |
| 边缘红线与物体分离 | 同帧同坐标对齐、RGB 分支缓存 | 调整边缘颜色或线宽掩盖错位 |
| 按一次键变化多次 | 按键同步、消抖、单脉冲生成 | 在算法端限制更新次数 |
| 半帧阈值不同 | 配置帧级提交、旧帧在途像素 | 仅降低按键响应速度 |
| DDR 冻结时撕裂 | 读写帧所有权、完整帧发布、换帧时机 | 把显示刷新频率降低但不查状态机 |
| 仿真正确但板上错误 | 真实 RAM/IP 模型、约束、CDC、复位、未初始化状态 | 直接怀疑算法理论 |
| Canny 长边缘断开 | 弱边缘传播范围、扫描依赖、队列溢出 | 只降低双阈值来掩盖连接缺失 |
| 识别只在演示纸张上有效 | 场景限制、特征定义、未测试的负样本 | 把“几何规则分类”称作通用识别 |
